# Контракт продукта с решателями `solver/`

Продукт (`dispatch/solve/runner.py`) запускает три бинарника из `solver/bin` отдельными процессами. На вход им
подаётся файл задачи, результат каждый пишет в stdout одной строкой JSON. Диагностика идёт в stderr. Ненулевой код
выхода означает ошибку (неверные аргументы, файл не открылся, ответ не разобран).

| Команда | Что делает |
|---|---|
| `plan <задача> [секунды=1] [сид=1]` | наш план: кооперативный поиск на всех ядрах, укладывается в заданное время |
| `baseline <задача>` | базовый вариант из раздела 2.3 ТЗ; остальные аргументы игнорируются |
| `fleet_bound <задача> <ответ plan> [секунды=3]` | нижняя граница числа бригад для заявок, которые обслуживает план |

## Файл задачи

Текст, числа разделены пробелами. Пишет его `Problem.write` из `dispatch/model/problem.py`, читает
`loadInstance` из `solver/src/core/problem.hpp`.

```
<имя>
N V S                                      заявок, бригад, стартовых точек
id длительность начало конец приоритет навык   × N
старт вид маска                                × V
матрица времени (S+N)×(S+N), затем матрица км  × 4 вида транспорта
```

- **Время** — в минутах от 10:00; смена длится 720 минут. `начало` и `конец` задают окно начала работ. Конец уже
  обрезан так, чтобы работа успевала закончиться до 22:00.
- **Приоритет:** 1 — авария, 2 — подключение, 3 — остальные. Штраф за невыполненную заявку — 100, 50 и 20.
- **Навык** — `s + 3·c`. Здесь `s` — сам навык: 0 — ремонт, 1 — подключение, 2 — авария. `c` — класс требования
  к транспорту (см. `Problem.skill_code`). Маска бригады: бит `навык` установлен, если бригада может выполнить такую
  заявку.
- **Вид транспорта** — индекс матрицы: 0 — машина, 1 — общественный транспорт, 2 — велосипед, 3 — пешком.
- **Точки** 0..S−1 — стартовые точки, S..S+N−1 — заявки. Строка матрицы задаёт, откуда едем.

## Ответ `plan` и `baseline`

```json
{"solver": "plan", "routes": [[3, 17, 5], [], [8, 2]], "feasible": true, "unserved": 0, "used": 2, "km": 41.275, "ms": 2910.4}
```

| Поле | Значение |
|---|---|
| `routes` | ровно V массивов: `routes[v]` — индексы заявок (0..N−1) бригады v по порядку; пустой — бригада не выезжает |
| `feasible` | все маршруты проходят проверку окон, смены и навыков с допуском 1e-6 мин |
| `unserved`, `used`, `km` | невыполненных заявок, выехавших бригад, суммарный пробег |
| `ms` | время работы |

Итоговые метрики продукт пересчитывает сам, а план независимо проверяет в `dispatch/planning/validate.py`. От
решателя продукту нужен только `routes`.

## Ответ `fleet_bound`

```json
{"fleet_lower_bound": 7, "lagrangian": 6.9981, "converged": false, "used": 7, "ms": 1204.7}
```

| Поле | Значение |
|---|---|
| `fleet_lower_bound` | меньше этого числа бригад заявки плана не обслужить; `null`, если оценку не успели получить |
| `lagrangian` | лагранжева оценка до округления вверх |
| `converged` | генерация столбцов сошлась: оценка равна оптимуму ЛП-релаксации |
| `used` | бригад в плане; если `fleet_lower_bound = used`, парк плана минимален |

Файл «ответ plan» — сохранённый stdout `plan`. Из него читается только поле `routes`.
