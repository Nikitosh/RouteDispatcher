# Решатели: прототипы и сравнение

Все решатели на C++ (`solvers/`), общий каркас `solvers/common.hpp`. Задача: открытые маршруты, у бригады своя
стартовая точка, вид транспорта и навыки, окно на начало работ, смена до 22:00.
Цель по приоритету: все заявки, затем минимум бригад, затем минимум км.

## Запуск

```
make                                   # собрать все решатели в bin/
bin/s12_alns instances/vostok_s0.txt 1 42   # задача, лимит в секундах, сид
.venv/bin/python bench.py 1 1          # все решатели и эталоны на 30 задачах, независимая проверка
.venv/bin/python bench.py 1 1 s12      # только решатели, в имени которых есть s12
.venv/bin/python sp_pool.py 10         # разбиение по пулу маршрутов из всех прогонов (CP-SAT)
```

Задачи в `instances/`: 3 участка по 10 случайных составов бригад (`export.py`). Эталоны: OR-Tools, PyVRP, VROOM
(`*_ref.py`, нужен `.venv`). Проверка `validate.py` не использует код решателей.

## Выводы

- Лучшие: ALNS, отжиг, HGS-lite, SISR. Уже за 0,2 с они используют меньше бригад, чем эталоны за 3 с.
- Минимум бригад в первую очередь даёт схема «удалить маршрут, вставить заявки, невставленные в пул с растущим штрафом».
- Графовые методы слабее как самостоятельные решатели. Оценка через покрытие путями бесполезна, оценка по нагрузке окон точнее.
- Пул маршрутов с CP-SAT улучшает пробег в 4 задачах из 30, максимум на 3,4 км.
- Решатели ограничены по времени, поэтому один и тот же сид может дать немного разные результаты.

# Этап 2: реальные дороги, улучшенные решатели, нижние границы

## Реальные дороги

Матрицы считает свой OSRM в Docker. Граф построен по выгрузке Geofabrik центрального федерального округа,
обрезанной до Москвы и юга области (`../osrm/`). Профили: машина, пешком, велосипед. Общественный транспорт:
пешком, если пешая дорога не длиннее 1,5 км; иначе 12 минут на подход и ожидание плюс дорога на машине со средней
скоростью 20 км/ч, а дальше 25 км 45 км/ч. Модуль `roads.py`, кэш `roads_cache_local/`.

Запуск серверов:
```
cd ../osrm
docker run -d --name osrm-foot -p 5001:5000 -v $PWD/foot:/data osrm/osrm-backend osrm-routed --algorithm mld --max-table-size 2000 /data/msk.osrm
docker run -d --name osrm-bike -p 5002:5000 -v $PWD/bicycle:/data osrm/osrm-backend osrm-routed --algorithm mld --max-table-size 2000 /data/msk.osrm
docker run -d --name osrm-car  -p 5003:5000 -v $PWD/car:/data osrm/osrm-backend osrm-routed --algorithm mld --max-table-size 2000 /data/msk.osrm
```

Наборы задач с реальными дорогами: `instances_control_road/` (12), `instances_road/` (30), `instances_gen_road/` (70).
Сборка: `ROADS=1 OUT=... python control.py`, `ROADS=1 python export_road.py`, `ROADS=1 OUT=... python gen.py`.

## Что не сработало
- Подкрутка долей времени s33 (RREND, SAF), адаптивная остановка сокращения парка (s50): размен «бригады против км» без выигрыша.
- Кандидаты гонки из одной базы без одной бригады (s52) и с нуля жадной вставкой с пределом K (s53): мало разнообразия / не укладываются.
- Сфокусированный удар с ремонтом для сокращения парка (s54, kick_util.hpp), план верхнего уровня «бригада × кластер × слот»
  (macro.py): на трудных задачах Юго-востока меньший парк требует обмена территориями между дальними бригадами, до которого
  эти приёмы не дотягиваются.

## Ловушки Юго-востока и подсказка-штраф
- На задачах с дальними домами решения бимодальны. Пример: `yugovostok_s0` — ямы около 400 и около 545 км.
- `guide.py` строит копию задачи со штрафом за км между кластерами. На ловушках это чаще приводит в хорошую яму,
  но в среднем по задачам с дальними домами выходит в ноль (s55_raceG, портфель s60 + s60 на подсказке, s63_coopG).
- Длинные прогоны с подсказкой на `yugovostok_s1…s9` сходятся ровно к лучшим известным значениям: разрывы 14–22% до
  нижней границы там, скорее всего, слабость границы, а не решений.

## Контрольные задачи: 24 (включая 12 со смешанным транспортом)
Лучшее известное: 167 бригад, 5770,4 км. Число бригад доказано оптимальным в 23, решение целиком — в 21.
