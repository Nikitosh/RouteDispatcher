## 02:20 s40_hy: точная переоптимизация пар маршрутов (ДП по меткам)
Идея: для пары маршрутов (a, b) перечислить все допустимые маршруты каждой бригады по объединению их заявок
(метки: маска, последняя, время, км; доминирование по (время, км) при одинаковых (маска, последняя)), затем выбрать
лучшую пару масок-дополнений (пустая маска = бригада освобождается).
* Без отсечений: пара по 11 заявок (control, машины) — >1,5 млн меток, не укладывается.
* Отсечение «мёртвых» заявок: заявки вне маски, до которых бригада уже не успевает, достанутся партнёру —
  мёртвое множество обязано быть допустимым маршрутом партнёра. Точная проверка (ленивая ДП по подмножествам)
  слишком дорога (7,7 млн состояний на пару), поэтому: попарная совместимость + жадные порядки (по началу, по концу,
  по середине окна) для |D|>6, точная ДП для |D|<=6. Итог: 50–20 000 меток на пару, пара за миллисекунды.
* Проверка: ДП всегда находит текущее разбиение (dpmin == cur) — отсечение не теряет текущий ответ.
* Результат: на решениях s10/s12 после 10 с улучшений почти нет (0 из 28, 0 из 10, 3 из 270 вызовов на трёх задачах).
  Пары у сильных решателей уже оптимальны; окрестность «пара целиком» ничего не даёт сама по себе.
* Полезным оказался сам конвейер: старт из s12 (10 бр, 351,1 км) -> отжиг SISR по км при фиксированном парке
  -> 332,3 км за 5 с (control_yugovostok_pt_all).

## 02:35 Сокращение парка внутри s40
* Тройки маршрутов -> две бригады (точная ДП): 0 успехов из ~100–110 попыток на каждой задаче (control_yugovostok_pt_inf,
  instances/yugovostok_s2, s5). Если 3 маршрута и сливаются, это уже нашли SA/ALNS.
* Старт из s10 (3 с, старый bench, 10 бр) на instances/yugovostok_s2 -> 9 бр 588,0 км; yugovostok_s5: 10 бр 621,5 ->
  9 бр 703,7 км (лучше s12 3 с: 704,0) — за 5 с. Проверка с NODP=1 даёт то же: бригаду убирает уже первый
  LocalSearch (relocate по одной заявке с бонусом 1e4 за опустевший маршрут) — у s10 выход не LS-оптимален по парку.
  Вывод: дешёвый LS lns_util поверх выхода s10 — обязательный шаг конвейера.
* «Фокусное» R&R-сокращение парка (удалить маршрут, R&R внутри области из 2–5 ближайших маршрутов) — 0 успехов
  на тех же задачах за 3 с (прототип `s40_hy_dev`), не включаю.
* Тёплый старт PyVRP (`hy_pyvrp.py`, initial_solution) работает (круговой тест 0,01 с сохраняет решение), но за 5 с
  не улучшил s10 10 с на control_yugovostok_car_all (319,6).
